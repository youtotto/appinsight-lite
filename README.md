# AppInsight Lite



## AppInsightシリーズでの役割

AppInsight Liteは、1つのアプリ内のフィールド使用箇所を点検する無料版です。検索・フィルター、フィールドごとのメモ、詳細画面でのコード表示を利用できます。

- **Lite（無料）**: 現在のアプリ設定とアップロード済みJavaScriptから、フィールドの使用箇所・参照候補を確認。
- **AppInsight**: JavaScriptや他アプリからの参照を含め、構成・依存関係・変更影響を調査。
- **AppInsight AI Review**: 解析結果の読み解き、確認事項と改善案の整理を支援。

Liteの「未検出」は削除して安全であることを保証しません。対象外の範囲や取得失敗も確認してください。

「このフィールド、どこで使っていたっけ？」を確認するための無料 kintone プラグインです。

アプリのフィールド一覧と、そのアプリの設定（計算式・ルックアップ・関連レコード一覧・一覧・通知・プロセス管理・グラフ・アプリアクション・アクセス権）の中で各フィールドがどこで使われているかを、プラグイン設定画面に一覧表示します。レコードのデータには一切触れない、読み取り専用のツールです。

- 📝 フィールドごとの開発メモ

## 主な機能

### フィールド一覧
- フォームのレイアウト順に、フィールド名称・フィールドコード・フィールドタイプ・必須・重複禁止・初期値を一覧表示
- サブテーブル内のフィールド、関連レコード一覧の表示フィールドは子行（┗）として表示
- レイアウトに置かれていないシステムフィールド（ステータス・作業者など）も表示

### 使用箇所の検出
フォーム内の全フィールドコード（サブテーブル内を含む）を起点に、次の設定から使用箇所を検出し、種類と対象名のバッジで表示します（例: `一覧: 顧客一覧`、`通知: 契約期限通知`、`グラフ: 月別売上`）。

| 種類 | 検出する設定 |
|---|---|
| 計算式 | 計算フィールドの計算式、文字列（1 行）の自動計算 |
| ルックアップ | ルックアップフィールド自身、「ほかのフィールドのコピー」のコピー先 |
| 関連レコード | 関連レコード一覧の「表示対象のレコードの条件」に使うこのアプリ側のフィールド |
| 一覧 | 表示する項目、絞り込み条件、並び替え、カレンダー形式の日付・タイトル |
| 通知 | アプリの条件通知の通知先、レコードの条件通知の条件式と通知先 |
| リマインダー | リマインダーの条件通知の基準日時・条件式・通知先 |
| プロセス管理 | アクションの実行条件、ステータスの作業者に指定したフィールド |
| グラフ | 分類する項目、集計方法の対象、並び替え、絞り込み条件 |
| アプリアクション | コピー元のフィールド、実行条件 |
| アクセス権 | レコードのアクセス権の条件式・対象フィールド、フィールドのアクセス権の対象フィールド |

条件式（絞り込み条件・並び替え・計算式）は、フィールドコードを識別子の境界で照合します。`date` と `update_date`、`A` と `ABC` を区別し、文字列リテラル（`"date"`）の中の偶然の一致は参照として扱いません。

### 検索・フィルター・件数
- フィールドコード・名称による絞り込み
- 「すべて / 使用箇所あり / 未検出」のフィルター
- 判定対象のフィールド数、使用箇所あり・未検出の件数、表示中の件数

### メモ
- フィールドごとにメモを残せます（プラグイン設定に保存。レコードには保存しません）

### レコード詳細画面のフィールドコード表示
- 設定でオンにすると、レコード詳細画面のフィールドラベルの横に `[フィールドコード]` を表示します
- サブテーブル内のフィールド、グループ、関連レコード一覧など、API で要素を取得できないものは対象外です

## 「未検出」について

**「未検出」は、そのフィールドが削除して安全であることを保証するものではありません。**

本ツールは、現在のアプリ設定の使用箇所と、アップロード済みJavaScriptの静的な参照候補を表示します。次のものは対象外で、これらで使われているフィールドも「未検出」と表示されます。

- URL指定/動的読込のJavaScript、CSS
- REST API 経由の参照（外部システム・連携サービス・他のプラグインからのアクセス）
- 他アプリからの参照（他アプリのルックアップの参照先・コピー元、他アプリの関連レコード一覧の参照先）
- カスタムビューの HTML
- プラグインの設定

また、設定の取得に失敗した項目（権限がない場合など）は判定に含まれず、画面上部に一覧表示されます。フィールドを削除・変更する前に、これらの対象外の利用箇所も必ず確認してください。

### AppInsight for kintone
他アプリからの被参照を含む依存関係の分析は、[AppInsight for kintone](https://www.nestrec.com/appinsight) で確認できます。本プラグインは 1 アプリを手早く確認する用途に絞っています。

## 使い方

1. kintone の「プラグイン」管理画面から本プラグインを読み込み、対象アプリに追加します
2. アプリの設定 → プラグイン → 本プラグインの「設定」を開くと、フィールド一覧と使用箇所が表示されます
3. 必要に応じてメモを入力し、「保存」を押します（メモと「フィールドコードを表示する」設定が保存されます）
4. 「レコード詳細画面のフィールドラベルの横にフィールドコードを表示する」をオンにして保存し、アプリを更新すると、詳細画面にフィールドコードが表示されます

設定画面を開く人には、アプリの管理権限が必要です。アクセス権（レコード・フィールド）などの設定を取得できない場合は、その旨が画面に表示され、取得できた設定だけで判定します。

## 現在アプリのJavaScript解析

- 公開済みのカスタマイズ設定（PC・モバイル）に登録されたアップロードJSを取得し、同梱Acorn 8.15.0で構文解析します。解析対象のJSは実行しません。
- メンバー参照、オブジェクトキー・分割代入、固定文字列・固定テンプレートとフィールドコードを照合。参照候補と文字列候補を区別し、ファイル名・行・列・抜粋・理由を表示します。変数名から対象レコードを断定しません。
- コメント・正規表現の本文は候補にしません。別名の追跡、文字列の組み立て、動的コード、外部読込、URL指定JS、プラグイン内部、他アプリからの参照は解析しません。解析済みは全参照の網羅を意味しません。
- URL指定・取得失敗・構文エラー・上限超過はファイル別に「解析できず」、動的プロパティ指定は「一部解析」と表示。各ファイル2 MiB、候補1000件、動的指定の記録は先頭100件まで。
- APIの適用範囲（ALL/ADMIN/NONE）も表示。NONEでも登録ファイルを解析するため、検出は実行中の証明ではありません。
- フィールド型・配置による絞り込みと、表示中のフィールド/使用箇所のCSVを追加。CSVには取得範囲と時刻を含め、BOM付きUTF-8・数式開始文字の無効化を行います。絞り込みで非表示になったメモも保存されます。
- 既存の関連レコードの表示先フィールド名取得は継続しますが、他アプリからの逆参照走査は追加していません。
- 本ツールは公開済み設定を使用します。フォームの未反映変更がある場合は、更新後に開き直してください。
